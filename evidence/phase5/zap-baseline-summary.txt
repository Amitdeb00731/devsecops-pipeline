Note on interpretation. The target is a headless machine-to-machine API with no
browseable root, so the ZAP spider receives HTTP 404 on / and the crawl is shallow.
The passive browser-hardening alerts configured in .zap/rules.tsv are accepted
(set to WARN with reasons) for the same reason: there is no browser surface for a
missing security header to protect. This is precisely why the dynamic access-control
probe, which calls the known privileged route directly, is the authoritative finding
rather than the spider-driven baseline. ZAP provides breadth; the probe provides the
binding depth, and the policy gate acts on the probe.

The full ZAP HTML report is produced in the run and retained as the dast-findings
build artefact (dast-out/zap-report.html) on each run linked above.
